Escenarios

El formato de .mocks/

Los mocks viven como YAML dentro del repo de tu app, así se versionan con las ramas y se comparten con un git pull. La estructura: 

tu-app/
└── .mocks/
    ├── project.yaml            # nombre + entornos
    └── scenarios/
        └── lista-vacia.yaml    # un fichero = un escenario

project.yaml

name: mi-app
environments:          # opcional
  local:
    api: ''            # vacío = la URL queda como pathname
  staging:
    api: https://api.staging.example.com

Los entornos definen variables reutilizables en las URLs de los mocks ({{api}}). El entorno activo se elige en la tarjeta de proyecto; su caso fuerte es separar dos hosts que comparten pathname.

Un escenario (scenarios/*.yaml)

name: Error al guardar          # obligatorio
description: El POST falla      # opcional
mocks:
  - name: Guardado roto         # opcional, para reconocerlo en las listas
    method: POST                # GET / POST / PUT / PATCH / DELETE / HEAD
    url: '{{api}}/api/items/'   # ver matching más abajo
    status: 500                 # código de respuesta, obligatorio
    delay: 400                  # opcional, milisegundos
    headers:                    # opcional, se añaden a la respuesta
      x-custom: valor
    response:                   # el body: YAML/JSON o texto plano
      errors:
        - internal error

El nombre del fichero es el identificador del escenario (se genera del nombre al crear desde la UI) y no cambia al renombrarlo, para que la activación no se pierda.

Matching de URLs

No hace falta escribir el host. Una URL de mock matchea contra la URL completa, origin + pathname o pathname, ignorando barras finales y la query string:

  • /api/items/ matchea https://cualquier-host/api/items/?page=2
  • api/items (sin barra inicial) matchea como fragmento: cualquier pathname que lo contenga
  • * es comodín: /api/items/*/photos/ matchea cualquier id intermedio
  • {{variable}} se sustituye por el valor del entorno activo antes de matchear

Qué NO va en los ficheros

La activación (qué escenarios y mocks están encendidos, el toggle global y el entorno activo) es estado del navegador: activar cosas no ensucia tu git status. Si dos escenarios activos mockean la misma URL, gana el último activado.
