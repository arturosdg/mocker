The .mocks/ format

Mocks live as YAML inside your app's repo, so they are versioned with your branches and shared with a git pull. The layout: 

your-app/
└── .mocks/
    ├── project.yaml            # name + environments
    └── scenarios/
        └── empty-list.yaml     # one file = one scenario

project.yaml

name: my-app
order:                 # optional: scenario order in the lists
  - empty-list
  - save-error
environments:          # optional
  local:
    api: ''            # empty = the url stays a bare pathname
  staging:
    api: https://api.staging.example.com

Environments define variables reusable in mock urls ({{api}}). The active environment is picked in the project card or the popup; its strongest use case is separating two hosts that share a pathname.

A scenario (scenarios/*.yaml)

name: Save error                # required
description: The POST fails     # optional
archived: true                  # optional: hides and deactivates it
mocks:
  - name: Broken save           # optional, to recognize it in lists
    method: POST                # GET / POST / PUT / PATCH / DELETE / HEAD
    url: '{{api}}/api/items/'   # see matching below
    status: 500                 # response code, required
    delay: 400                  # optional, milliseconds
    headers:                    # optional, added to the response
      x-custom: value
    response:                   # the body: YAML/JSON or plain text
      errors:
        - internal error

The file name is the scenario id (generated from the name when created from the UI) and does not change on rename, so activation state is never lost.

URL matching

No need to write the host. A mock url matches against the full url, origin + pathname or pathname, ignoring trailing slashes and the query string:

  • /api/items/ matches https://any-host/api/items/?page=2
  • api/items (no leading slash) matches as a fragment: any pathname containing it
  • * is a wildcard: /api/items/*/photos/ matches any id in between
  • {{variable}} is replaced with the active environment's value before matching

What does NOT go in the files

Activation (which scenarios and mocks are on, disabled domains and the active environment) is browser state: turning things on never dirties your git status. When two active scenarios mock the same url, the last activated one wins.

WebSockets: emitting server pushes

The popup's WebSockets · this tab section lists the page's live sockets and lets you inject a message as if the server had sent it: pick a socket (or leave the url filter empty for all), write a channel and data, and Send. With a channel, the frame is wrapped in the Centrifugo v2 envelope — {"push":{"channel":"…","pub":{"data":…}}} — so a centrifuge client routes it to that channel's subscription; with no channel, the data is sent as a raw frame. The message is injected over the page's real connection, so the client must already be connected and subscribed.

Frequent pushes can be saved in .mocks/websockets.yaml (WebSockets tab, or by editing the file — it is shared through git like everything else) and fired with one click from the popup: 

messages:
  - name: New task push
    url: centrifugo          # optional: socket url filter
    channel: tasks:123       # optional: empty = raw frame
    data:
      count: 2

For agents: .runtime/ logs

With the project connected, mocker dumps the last 50 captured requests to .mocks/.runtime/requests.json and the last 50 WebSocket frames (both directions) to .mocks/.runtime/websockets.json. An agent can edit the YAML files directly and read those files to verify what was called and what matched — without opening a browser. Both logs are purged at the start of each browser session. Add .mocks/.runtime/ to your .gitignore. 

{
  "updatedAt": "2026-09-02T12:00:00.000Z",
  "requests": [
    {
      "at": 1788350000000,        // epoch ms
      "origin": "https://localhost:3000",
      "tabId": 123,
      "method": "POST",
      "url": "https://localhost:3000/api/items/",
      "requestBody": "{\"name\":\"x\"}",   // payload sent (≤32KB)
      "status": 500,
      "body": "{\"errors\":[...]}",        // response received (≤32KB)
      "mocked": true,                      // served by mocker
      "scenario": "save-error",            // scenario that matched
      "mockName": "Broken save",           // if the mock has a name
      "mockUrl": "{{api}}/api/items/"      // the mock url that matched
    }
  ]
}

Requests without mocked are real traffic that passed through (with its captured response): raw material for new mocks.
